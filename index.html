04 / INSIDE THE VEHICLE

一台车内助手，需要一条完整链路

点击环节查看关键约束。语言模型只是其中一部分，任务是否离线取决于整条路径。

先确定计算设备与部署权

CarPlay / Android Auto

应用以手机为基础，车内接收界面与音频。应用上屏不等于模型部署到接收主机。

AAOS / 后装 Android 设备

可以提供车内应用运行环境。仍需逐项核实算力、后台运行、麦克风、音频焦点与车辆接口。

依据：Apple CarPlay 指南、Android Auto、AAOS 定义。展开平台与商业背景 ↗

MEMORY

权重能放下，整机未必够用

1.7B 参数按理想 4-bit 权重约为 0.85GB。运行时还要加缓存、识别、播报、应用和系统占用。这个估算不是最低内存承诺。

LATENCY

首 token 不是首次听到回复

NXP 的英语开发板示例采用 500M 模型，首 token 0.28 秒，首音频 3.27 秒，平均内存 4794MB。条件不可直接推广到实车。核查官方条件 ↗

05 / ENTRY STRATEGY

从可交付的任务切入

以下为研究判断。新增竞品表明“本地运行”已有参与者，差异需要在车内完整体验、适配和交付中证明。

A
优先验证

成熟后装硬件上的本地语音任务模块

与能提供系统和音频接口的厂商合作，先覆盖少量高频任务：本地手册、常用信息与授权操作。与现有本地 Launcher 比较任务成功、噪声体验、启动、离线范围和支持成本。

进入前提
固定硬件与固件、可用音频链路、合法接口和模型许可。
投资判断
真实用户持续使用与单位贡献先于扩张。SDK 授权或按设备收费是候选模式。
B
并行比较

控制拾音与交互的独立车载设备

自带麦克风、按键与本地算力，可能更容易控制体验；也增加供电、散热、原车音频协作、库存与售后责任。需证明增加设备的收益能覆盖全周期成本。

C
后续独立评估

驾驶辅助是一条新的工程与商业路径

车上已有驾驶模型产品可作参照，但语音用户、渠道和对话数据不能直接替代车辆接口、感知控制、安全验证与道路数据。是否进入，以能力与资源证据判断。

投资前，先取得四组证据

  1. 用户收益相对手机和已有产品，任务是否更容易完成、会否再次主动使用。
  2. 交付可靠性噪声、断网、热稳态、启动、音频抢占与安装工时。
  3. 经营可行性净售价、设备与许可、渠道、退货质保、长期更新和现金周转。
  4. 渠道匹配用实际客群和安装售后能力评估渠道。波兰仅作为可进一步核验的区域案例。
